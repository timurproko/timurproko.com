Overview

A1 runs in your terminal next to whatever editor you already use. You describe a task and the agent reads files, edits code and runs commands in your project, using the model provider you choose.

I design and build it — product, terminal UI and release pipeline — and develop it with coding agents working from written specs. The code is on GitHub under the MIT license.

Challenge

Pi's extensions are built for adding tools, not reshaping the interface, and ideas like a multi-agent workspace would never fit inside it.

So I built A1 on top with its own abstraction: Pi stays the engine, A1 owns the experience. The hard part is reaching Pi only through its public SDK, so extensions and upstream updates keep working.

Process

  1. Built on Pi's public SDK. Pi is the agent engine behind A1's own interface, without patching Pi's internals, so upstream updates and Pi extensions keep working.
  2. Its own everyday UX. A settings screen, a custom session viewport, persistent prompt history and next-step suggestions, with a separate profile in ~/.a1/agent.
  3. Spec-driven, agent-assisted work. Each change starts as an OpenSpec proposal with tasks and acceptance checks, is implemented by coding agents in isolated worktrees, and reaches develop only after validation — 280+ changes so far.
  4. Gated releases. Numbered preview builds on npm, nightly and Windows regression runs, and stable releases that publish to npm only after the draft passes validation.
